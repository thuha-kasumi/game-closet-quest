CLOSET QUEST · FIRST EDITION

From this folder
to your first live game.

You do not need to write any code. The project files are complete. Your job is to upload them, publish the server, test the public link with a friend, and submit the result.

The path: Extract the ZIP → upload its contents to GitHub → connect Render → test your public game → submit on Handshake.

This guide was prepared October 31, 2026. Button labels may vary slightly. The linked official provider guides are included below.

1. Download and extract the project

  1. Download Closet-Quest-Starter.zip from our conversation.
  2. On Windows, right-click the ZIP → Extract All… → Extract.
  3. Open the extracted folder. You should see package.json, server.mjs, index.html, and the other files listed below.
  4. Open this START-HERE.html file to keep the guide beside you. Keep COVER.png handy for Handshake.
You do not paste the code into ChatGPT, Handshake, or Render. The code goes into a GitHub repository as files. Render runs those files and gives you the public website link.

Double-clicking index.html does not launch the multiplayer game. It needs its server; use the publishing steps below.

2. Upload the files to GitHub

  1. Sign in to GitHub.
  2. Click + near the top → New repository. Name it closet-quest (or closet-quest-game if that name is taken in your account).
  3. Suggested description: A multiplayer styling party inspired by real dorm-room closets. Create outfits, reveal together, and vote with friends.
  4. Choose Public if you want the code visible in your portfolio. The supplied files contain no passwords or API keys. Leave the optional starter README, license, and .gitignore choices unselected for this empty repository.
  5. Click Create repository.
  6. On the empty repository page, choose uploading an existing file. If the repository already has a file, use Add file → Upload files.
  7. Open your extracted folder. Select the files inside it and drag them into the GitHub upload area. Upload the files themselves, not the ZIP and not an extra enclosing folder.
  8. Enter Launch Closet Quest first edition as the commit message. Commit the files to your new repository’s default branch.
  9. Confirm that package.json and server.mjs appear immediately in the main file list. You should not need to open another folder to reach them.

Expected files: app.mjs · art.mjs · catalog.mjs · favicon.svg · game.mjs · game.test.mjs · index.html · package.json · package-lock.json · README.md · render.yaml · server.mjs · styles.css · START-HERE.html · COVER.png

GitHub’s browser upload instructions: Adding a file to a repository.

3. Publish on Render

  1. Open Render’s dashboard. Sign in or create your own account. Review any account terms yourself.
  2. Choose New → Web Service. Web Service is essential: this game needs a running server.
  3. Connect your GitHub account when asked, and grant access to the closet-quest repository. You can limit repository access if that option is offered.
  4. Select your repository and choose Connect or the equivalent setup button.
  5. Use the settings in this table. If something differs, match the purpose of the field.

  1. Click Create Web Service or Deploy Web Service.
  2. Wait for the deployment to finish. The log should include Closet Quest is ready on port … and Render should show that the service is live.
  3. Open the onrender.com URL shown in your own dashboard. Its exact address depends on your service name and availability.
  4. You should see the Closet Quest home page with “Big looks. Small closet.” This is your submission URL.
Free hosting: Render’s free web services sleep after 15 minutes without incoming traffic. The next visit can take about a minute to wake the service. This game keeps room state in memory, so a restart, redeploy, or shutdown clears old rooms. New groups can create fresh rooms after the service wakes. Leave the game on one instance. Free hosting is subject to current account availability and usage limits; no paid plan is required by this code.

4. Run a real multiplayer test

Test the public Render URL, not the GitHub repository page. A roommate’s phone is ideal; a private/incognito window can stand in for a second player if needed.

  1. On your laptop, enter a nickname and click Create a room.
  2. Choose Copy invite and share that link with your tester yourself, or tell them the six-character code.
  3. On the other device/window, enter a different nickname and click Join friends. Confirm that both names appear on both screens.
  4. As host, type Hard-rock party into the optional occasion field and start.
  5. Select clothing on each device. Try a layer, shoes, extras, skin/hair choices, a short caption, and a filter such as rock.
  6. Before locking, refresh one player’s page once. Confirm that it reconnects and restores that player’s last saved outfit. Give selections a second to save before refreshing.
  7. Lock each look. Confirm that both devices switch to the reveal and display both outfits.
  8. Rate the other look in both categories and submit on each device. Confirm that both show the same scores.
  9. Use the host’s Next occasion button to complete three rounds. Confirm that the final totals and winners agree.
  10. Try Save outfit card and check that a PNG downloads. Finally, return to the lobby and confirm that a fresh game can start.
  • Public URL opens on a phone.
  • Two different players can join without an account.
  • Both screens share the prompt, reveal, and results.
  • Outfits are private until reveal.
  • Voting and all three rounds work.
  • Instructions are easy to find.
  • PNG save works in the tester’s browser.

Automated server tests were run during preparation. This device test is still essential: it checks your actual deployment, browser behavior, and network connection. The development environment did not allow a full visual browser acceptance test.

Description to copy

Closet Quest is a multiplayer styling party inspired by a real problem in my dorm: having plenty of clothes, but forgetting what is there and struggling to imagine new combinations. Two to six players join a room from their own phones or laptops, style cartoon avatars for a shared occasion, reveal their outfits together, and rate each other’s choices for occasion fit and creativity. Three rounds turn a shared illustrated wardrobe into a playful way to explore personal style. I developed the concept and built this first edition with ChatGPT. It includes room-code invitations, synchronized game phases, timed rounds, outfit captions, keyword filters, avatar customization, and downloadable outfit cards. Players need no account or installation. This version uses a shared starter wardrobe. Personal clothing uploads and a private wardrobe organizer are planned future features. Rooms are temporary and reset on server restart; the free demo host may take about a minute to wake after inactivity.

If something goes wrong

What you seeWhat to do
Render cannot find package.jsonThe files may be inside an extra folder. Put them at the repository root, or set Root Directory to that exact folder name.
Render asks for Publish DirectoryYou likely selected Static Site. Create a Web Service instead.
Build failsCheck that Build Command is npm install, Start Command is npm start, and the .mjs files kept their names. Copy the final relevant error lines into our chat if help is needed; leave out credentials.
A long loading page after inactivityWait about a minute for the free service to wake, then retry once.
“Room not found”Check the room code. If the server restarted or was redeployed, create a new room.
“This game has started”New players join in the lobby. Finish the round and have the host return to the lobby.
Two windows behave as the same playerUse a separate private/incognito window, another browser profile, or another device. Duplicated tabs may inherit the same player session.
Clipboard copying is unavailableShare the six-character code manually. Friends open the same game home URL and enter it.
Reconnecting…Check your network. The game retries its live connection automatically. A normal refresh can restore the session while the room exists.
Host disappearsAn active player becomes host after the original host stops checking in for roughly 45 seconds. Timed styling and voting still finish automatically.
A player leaves midwayWith two or more players remaining, the game continues; if only one remains, it returns to the lobby. The host can remove absent players between rounds.
